## 3. core と手動計器の一致（規則の正本が 2 つある件）

`core/selection_metrics.classify_hallucination` + `nearest_catalog_name` と
`scripts/skillsel_reading.py::classify` を、同じ窓の distinct rejected 名すべてに当てた:

| 窓 | distinct rejected | 機構の不一致 | 最近傍の不一致 |
|---|---|---|---|
| 2026-08-29〜09-04 | 36 | **0** | 3 |
| 2026-08-23〜09-05 | 54 | **0** | 5 |

最近傍が割れた 5 件の類似度はいずれも 0.37〜0.57 で、語形変化の床 0.90 をはるかに下回る。
原因は 3 つ: `SequenceMatcher.ratio()` が非対称で被演算子順が逆 / core が `autojunk=False` を
渡し script は既定 / core は `sorted(catalog_names)` を回し script は入力順。
実害は「延べ 1 件がどちらの entry に計上されるか」で、2026-09-05 の窓では実際に動く
（script 側の規則で回すと候補は `shifting-focus-to-systemic-degradation-gradient` になる —
これも never-selected strict に既にいる名前なので候補ファイルは変わらない）。

機構の一致が 90 件中 0 不一致であることが、`tests/test_skill_confusion.py` の parity test が
守っている性質そのものである。script 側は変えない（被演算子順を変えると
`docs/evidence/rfc-0014/` の凍結値が動く）。
