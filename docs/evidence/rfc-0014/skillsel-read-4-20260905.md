## 6. 読めなかったもの（交絡）

- **エントリ数 vs corpus トークン** — §4.2 のとおり、分離を担う唯一の対（50 vs 57）が n=23 側で
  CI 36pt 幅。第 3 窓で得た対（45 vs 48）と合わせて 2 対あるが、どちらも他の要因（改名・本文書き換え /
  1 日だけのレジーム）を抱えており、率をどちらに帰属するかは決まらない。
- **頭のすげ替えの原因** — §2 の +21pt / −24pt は catalog も description も動いていない窓で起きて
  いるので、残る候補は「入力（状況）側の分布が変わった」「08-22 採用 9 件が選択枠を奪い合った」の 2 つ。
  本読みは選択の並びしか見ておらず、状況側の分布は見ていない（`prompt_b64` を decode しないため、
  本読みの範囲では原理的に見られない）。
- **意味的取り違えの増加（9.4% → 18.5%）** — 分類は最近傍類似度 0.90 の線で切っており、
  カタログが 48 → 57 に増えて最近傍が近づけば同じ文字列が語形変化側に寄る（逆も同じ）。
  **閾値の効きとモデル挙動の変化を分離していない**。第 2 窓の再集計が完全一致していることは
  「規則が同じ」ことの証拠にはなるが、「規則が catalog サイズに対して中立」の証拠ではない。
- **分類規則の「凍結」は今日時点の凍結** — 規則 2（値層混入）は「カタログ語彙に無く値層にある
  トークン」を見るが、そのカタログ語彙はスクリプト実行時点の store から取る。store が育つほど
  「カタログ外」の集合は縮み、過去窓の一部の名前が値層混入から語形変化 / 意味的取り違えへ移りうる。
  §0 の「第 2 窓を完全に再現した」は**今日再実行すれば再現する**という意味で、次の採用が入った後も
  同じ行が出る保証ではない。規則 3 の閾値と同型の非中立性。
- **`boundary-assumption-verification` の description 差分** — 第 3 読みからの持ち越し。未照合。
- **自己言及ループ**（選択→生成→蒸留→skills）— 3 窓連続で読めていない。この窓は catalog が
  固定だったので、次に採用が入る窓が最初の観測機会になる。
