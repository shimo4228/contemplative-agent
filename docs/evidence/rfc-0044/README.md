# RFC-0044 第 2 段 — enum 拘束の受入測定（2026-09-26）

[RFC-0044](../../../rfcs/0044-skill-selector-temperature-zero.md) の第 2 段（skill selection の判断コールに
catalog 名の enum 拘束を入れる）を、RFC の受入条件 3 つで判定した測定と、上限 1 / 3 の追加測定（S34）、
Jev との件数を揃えた比較。**帰結: 第 2 段は見送り**（オーナー決定 2026-09-26、末尾「決定」節）。実装（S33、
`bea29f1`）は main に入れていない。

| ファイル | 中身 |
|---|---|
| `skillsel-enum-s33-20260926.json` | arm ごとの集計（verdict 内訳・幻覚・選択数の分布・出力 tokens・latency）、行ごとの対の差、天井 arm との一致、本番セッションあたりの selection 回数、標本の `selection_id`。本文・名前は含まない |

## 条件

- 標本: [RFC-0043](../rfc-0043/README.md) 第 1 ラウンドと同じ 150 行（記録上の幻覚あり 75 / なし 75 に層別）。
  新しく引き直していない — 前回の arm と行単位で対にできるため
- 経路: 本番の `core.llm._post_ollama` と同じ payload を Ollama に直接送る（`scripts/skillsel_arm_replay.py` の
  `ollama_generate`。違いは counters を受け取ることだけ）。prompt は記録された prompt そのもの、system prompt は
  今日の identity + 憲法から再構成（RFC-0043 と同じ制約）
- Ollama 0.34.2、gemma4:e4b、temperature 0、`think=False`。arm は直列・arm ごとに 150 行を同じ順で回した
  （前の呼び出しが同じ arm の前の行になるので、prefix cache の条件が arm 間でそろう）。他のモデルは載っていない
- 3 arm:
  - **free**: 現行（自由生成、`num_predict=400`）
  - **enum**: `format=` に catalog 名の enum 配列（arm B と同じ schema）、`num_predict=1024`
  - **enum + maxItems 10**: 上に `maxItems: 10`（free の p90）。受入条件 (b) を enum 単独で満たせなかったため、
    packet が許した 1 回だけの試行

prompt 評価時間の中央値は 3 arm とも 3.6〜3.7 秒で、cache 条件はそろっている。latency の絶対値は
対話中の機械（swap 約 6 GB 使用中）の値で、比較に使えるのは arm 間の差。

### 受入条件

- **(a) parse_failed 0** — enum 単独は `num_predict=1024` で 0。400 のままなら 3 行（出力 560〜590 tokens）が
  配列の途中で切れて parse_failed になる。maxItems 10 では最大 161 tokens なので、**400 で 0**（temperature 0 の
  greedy 復号は `num_predict` で出力が変わらず、打ち切りだけが変わる — 1024 で測った出力長から導いた値）
- **(b) 選択数の上限側が自由生成の分布を超えない** — enum 単独は **不合格**（p90 15.1 対 10、最大 44 対 39、
  11 件以上の行 33 対 9）。maxItems 10 で p90 10・最大 10 となり合格。代価として 45 / 150 行（30%）が上限に
  張り付く。その上限が判断の質を削っていないかを天井 arm（RFC-0043 の opus-5）で見た: 対の差の Jaccard は
  maxItems 10 − enum 単独 = +0.005（95% CI [+0.001, +0.010]）、maxItems 10 − free = +0.022（[+0.008, +0.035]）。
  上限は量を切っているだけで、天井との一致は下がっていない
- **(c) latency の増分が本番の窓に収まる** — 本番の selection 回数は `logs/skill-selection-*.jsonl`
  （2026-09-12〜26 UTC、57 セッション、judged 1,189 件）で 1 セッション平均 20.9 回・p90 24・最大 25、
  セッションは 60 分。maxItems 10 の増分は平均 1.9 秒 × 20.9 回 = 40 秒（**1.1%**）、悪い側で見積もっても
  p90 の 4.3 秒 × 最大 25 回 = 108 秒（3.0%）。合格。セッションは時間で区切られるので、増分は延長ではなく
  アクションの取り分として効く

判定: **enum + maxItems 10、`num_predict=400` で (a)(b)(c) を満たす。enum 単独は (b) で落ちる。**

### 標本が言えないこと

- 層別標本なので幻覚率 5.3% は本番の予測ではない（本番の t=0 は 2.6〜3.0%、RFC-0044 の 2026-09-26 節）
- 天井は opus-5 の 1 反復で、正解ではない（RFC-0043 の Drawbacks）
- 上限に張り付いた 45 行で「どの 10 件が残るか」は gemma の出力順で決まる。その順の意味は測っていない
- 本番の Ollama は他の呼び出しと交互に動くので、cache 条件はこの測定より悪い。増分の比率は同じ桁と見ている（推論）

## 追加測定 S34 — 上限 1 / 3（2026-09-26 19:08〜19:51 JST、同じ 150 行・同じ条件）

| | free | enum | max10 | max3 | max1 |
|---|---|---|---|---|---|
| opus 天井との Jaccard | 0.164 | 0.180 | 0.185 | 0.115 | 0.052 |
| precision（選んだものが天井の集合に入る率） | 0.260 | 0.261 | 0.280 | 0.293 | 0.300 |
| recall（天井の集合を拾えた率、147 行） | 0.299 | 0.363 | 0.338 | 0.150 | 0.053 |
| 最頻 skill を選んだ行 | 75.3% | 80.0% | 74.7% | 50.7% | 33.3% |
| 150 行で選ばれた skill の種類 | 50 | 49 | 40 | 29 | 14 |
| latency 中央値（秒） | 8.43 | 10.83 | 10.77 | 7.94 | 6.31 |

parse_failed と空選択は全 arm で 0。

**この表の天井比較は条件が揃っていない**（オーナー指摘）: 天井の opus-5 は上限なし（平均 5.97 件）で選んでおり、
上限 1 / 3 の arm だけに件数の制約がある。recall の低下は主にこの非対称から来ており、上限の小さい arm の質は
この表からは言えない。

**天井に依存しない読み — 上限は関連度でなく出力順で切る**: max1 の 1 件は 150 / 150 行で max10 の答えの中にあり、
120 行でそのアルファベット順の先頭。max10 が上限に張り付いた 45 行は、上限なし enum の答えの部分集合が 45 / 45、
アルファベット順の先頭 10 件と一致が 21 / 45。上限が効く行では、名前の後ろの skill ほど落ちる — 選択ログを材料にする
退役判断（never-selected）が名前順に歪む。

## Jev との件数を揃えた比較（2026-09-26、既存の Jev 行データ、追加費用なし）

Jev（TypeSafe、ホスト）は skill ごとの確率を返すので、上位 k 件に揃えて gemma の上限 k と比べられる。Jev は同じ
150 行で opus 天井との Jaccard 0.346・1 行 0.32 秒（ADR-0112、MCA 2.3 の改定で公開可）。

| 比べ方 | Jev choice | Jev noul |
|---|---|---|
| gemma max1 の 1 件 = Jev の 1 位 | 12.0% | 6.7% |
| gemma max1 の 1 件が Jev の上位 3 に入る | 24.0% | 18.7% |
| gemma max3 と Jev 上位 3 の重なり | 19.8% | 17.1% |
| Jev の 1 位が gemma max10 の答えに入る | 41.3% | 46.0% |

無作為の 1 件が Jev の 1 位に当たる率は約 1.9%、上位 3 に入る率は約 5.5%。gemma の 1 件選択は Jev の 1 位と
1 割前後しか合わず、10 件選ばせても Jev の 1 位を含むのは半分弱。

## 決定（オーナー、2026-09-26）

第 2 段（enum 拘束）は見送る。temperature 0 の自由生成（幻覚 2.6%、存在しない名前はコードが弾き実害なし）のまま。
上限は関連度でなく出力順で切るので入れない。上限なしの enum は選択数が増える（平均 7.0 → 8.9）。gemma の
skill 選択そのものが弱い（opus 天井との一致 0.14〜0.19、Jev 0.35、opus 自己一致 0.68）ことは、選び方を磨く
より store の件数を絞る方向で扱う — [RFC-0048](../../../rfcs/0048-skill-store-self-maintenance.md) の 2026-09-26 追記。
