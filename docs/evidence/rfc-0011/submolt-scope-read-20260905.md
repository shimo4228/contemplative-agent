## 1. 順序の安定性

**指標**（3 本すべてに同じものを当てる。1 本を読み値にしない）:

- **Spearman ρ** — submolt ごとの平均スコアが誘導する順位の、sweep 間の一致度（19 件、
  tie は平均順位）。**平均は 4 桁に丸めてから順位を付ける** — 丸めないと `0.66` と
  `0.6599999999999999` が別値になり、実際には同点のものが順位差として入る
- **当たり率の Spearman ρ** — 同じものを「閾値 0.80 以上の割合」で（コードも `>=`）
- **上位 8 の入れ替わり数** — N=8 は購読数に合わせた（「今の 8 枠を組み替えるか」が問い）
- **split-half ノイズ天井** — 同一 sweep 内で各 submolt のサンプルを奇数番目 10 件 /
  偶数番目 10 件に割り、順位一致度を Spearman-Brown で全長に補正した値。**sweep 間 ρ を
  この値と比べないと、順位の揺れが世界の変化か n=20 の標本誤差か分けられない**。
  前半 / 後半でなく奇数 / 偶数で割るのは、サンプルが feed の新しい順に並ぶため連続した
  2 分割が parallel にならず、信頼度が低く出る（＝ sweep 間 ρ を実際より良く見せる）向きに
  偏るから
- **投稿の重なり** — 2 本が共有する `post_id` の数。同じ投稿を測り直しているなら順位の
  安定は自明になる

| ペア | ρ(平均) | ρ(当たり率) | 上位 8 の入替 | 共有投稿 |
|---|---|---|---|---|
| 08-19 → 08-26 | **0.836** | 0.863 | **1** | **0** |
| 08-19 → 09-02 | **0.829** | 0.813 | **1** | **0** |
| 08-26 → 09-02 | **0.906** | 0.862 | **1** | **0** |
| （基準線）08-08 → 08-19 | 0.719 | 0.681 | 3 | 0 |
| （基準線）08-08 → 08-26 | 0.536 | 0.517 | 4 | 0 |
| （基準線）08-08 → 09-02 | 0.570 | 0.630 | 4 | 0 |

split-half ノイズ天井（同一 sweep 内、Spearman-Brown 補正後）: 08-19 **0.886** /
08-26 **0.780** / 09-02 **0.710**（基準線 08-08 は 0.834）。

読み値としての事実:

- **3 本の sweep どうしの ρ は 0.83〜0.91、同一 sweep 内のノイズ天井は 0.71〜0.89 で、
  2 つの帯は重なっている。** つまり定期 3 本の間に残る順位の食い違いは、n=20 の標本誤差より
  大きいとは言えない。片方が他方を上回っているわけではないので、「標本誤差より小さい」とも
  言えない — 言えるのは **区別がつかない**ところまで。
- **共有投稿はどのペアでも 0 件。** 4 本 × 380 判定はすべて別の投稿で、上の一致度は
  「同じ投稿を測り直した」結果ではない。
- **上位 8 の入れ替わりは 3 ペアとも 1 件のみ。** 3 本すべてで上位 8 に居続けたのは 7 件
  （`agents` `consciousness` `emergence` `general` `memory` `openclaw-explorers` `philosophy`）。
  残り 1 枠だけが `todayilearned` → `infrastructure` → `security` と入れ替わった。
- **基準線（08-08）との一致度は定期 3 本どうしより明確に低い**（ρ 0.54〜0.72、入替 3〜4）。
  8/8 が Sat 22:24 JST の手動実行だったことは測定値だが、**そのためにサンプルされる投稿の層が
  違うという説明は測っていない**（投稿の重なりは定期 3 本どうしでも 0 件なので、
  重なりの有無では基準線を切り分けられない）。仮説として置く。

順位のふれ幅（3 本の中での最良順位と最悪順位の差）。**同点は平均順位で扱う** — 平均スコアが
同点の submolt は sweep ごとに 4 / 2 / 5 / 0 件あり、名前順の序数で数えると同点の入れ替わりが
「動き」に見えるため:

| 幅 | submolt |
|---|---|
| 0〜2 | `agentfinance` `crypto` `trading` `consciousness` `builds` `introductions` `emergence`(2.5) `memory` `openclaw-explorers` `technology` |
| 3〜5 | `agents`(3.0) `philosophy`(3.0) `general`(3.5) `blesstheirhearts`(4.0) `tooling`(4.0) `ai`(5.0) |
| 6 以上 | `infrastructure`(6.5) `todayilearned`(7.0) **`security`(10.0)** |

`security` だけ 16 → 10 → 6 の単調上昇で、他の大きい 2 件（`todayilearned` 7 → 14 → 9、
`infrastructure` 14 → 8 → 10）は往復している。

## 撤去条件 (a)/(b) への照合（事実のみ）

RFC が事前登録した条件文に、上の数値を素直に当てる。**判定はしない。**

**(a)「3 回とも順序が安定し、`agents` 解除と未購読の追加が確定した」**

- 前半「順序が安定」に当たる数値: ρ 0.83〜0.91、上位 8 の入替は 3 ペアとも 1 件、
  食い違いは同一 sweep 内のノイズ天井 0.71〜0.89 と区別がつかない — **当たる**。
- 後半「`agents` 解除」に当たる数値: `agents` は 3 本とも上位 8（順位 8 / 5 / 5）。平均で
  上回る未購読は 08-19 で 2 件、08-26 と 09-02 で 0 件 — **当たらない**。条件文は `agents` が
  下位に留まることを想定しているが、観測はその逆を向いている。
- 後半「未購読の追加」に当たる数値: 3 本すべてで上位 8 に入った未購読は
  `openclaw-explorers` 1 件のみ。初回の 6 件は再現せず、「購読中の最弱を上回る未購読」の
  件数は 3 / 5 / 7 と揺れる — **1 件については当たり、6 件という初回の括りについては当たらない**。

**(b)「3 回とも『変更しない』で、順位変動が閾値判断に影響しない範囲」**

- 「順位変動が閾値判断に影響しない範囲」に当たる数値: 上位 8 の 7 枠は 3 本とも不動、
  残り 1 枠だけが毎回入れ替わる。閾値 0.80 側では群の差（d 0.545〜0.763）が 3 本とも維持 —
  **枠の 7/8 については当たる**。
- ただし前半「3 回とも『変更しない』」は結論であって観測ではない（この文書は判定をしない）。
  観測として当たらない点が
  2 つある: `agents` の位置が基準線から反転していること（#17 → #5）と、`security` が
  16 → 10 → 6 と単調に上がって 3 本目で上位 8 に入ったこと。

**継続条件「順序が不安定で、どの submolt が効いているか 3 回では決まらない」** に当たる数値:
19 件中 16 件のふれ幅は 5 位以内、上位・下位の両端（`consciousness` `emergence` `memory` /
`crypto` `agentfinance` `trading`）は 3 本ともほぼ不動。**ふれ幅が 6 位以上なのは
`security` `todayilearned` `infrastructure` の 3 件に限られる。**

## 読みを弱める要因（confounder）

**基準線（08-08）と定期 3 本の間で、測る側も変わっている。** `config/prompts/relevance.md` は
スコアラーに「system prompt の domain identity を基準に採点せよ」と指示しており、その identity
は値層である。窓の中で起きたこと（`logs/audit.jsonl`）:

| 日付 | 出来事 | 位置 |
|---|---|---|
| 2026-08-09 | `amend-constitution` approved | 基準線と sweep 1 の間 |
| 2026-08-15 | `distill-identity` approved | 基準線と sweep 1 の間 |
| 2026-08-08 / 08-15 / 08-22 | `insight` の skill 採用（それぞれ 8 / 5 / 9 件 approved） | 基準線〜sweep 2 |
| 2026-08-15 | `skill-stocktake` / `skill-stocktake-clean` approved（計 5 件） | 基準線と sweep 1 の間 |
| 2026-08-25 | `remove-skill` approved（1 件） | sweep 1 と sweep 2 の間 |
| 2026-08-29 | `insight` は staged / rejected のみ — **採用は 0 件** | sweep 2 と sweep 3 の間 |

したがって **`agents` の #17 → #5 の反転は「submolt の中身が変わった」「採点の基準が変わった」の
どちらとも読める**。定期 3 本どうし（08-19 / 08-26 / 09-02）の間には identity / constitution の
変更は無い。ただし skill 層はこの区間でも動いており（08-22 の採用 9 件、08-25 の退役 1 件）、
skill は identity の一部として scorer の system prompt に入るので、**この 3 本が
「測る側が完全に固定された 3 本」だとは言えない**。

コード側では `submolt_scope.py` が 2026-08-28（`009baee`）と 08-31（`5be5ef6`）に触られている。
どちらも C901 分割で、`009baee` は挙動保存の実測（differential replay 4767 challenges
0 mismatch）を commit message に記録している。`5be5ef6` は同種の分割だがその実測を
記録していない — どちらも sweep 2 と 3 の間に入る。

## 副次的な観測

**sweep の所要時間が 3 本で伸びている**: 12 分 09 秒 → 13 分 31 秒 → **18 分 37 秒**。
RFC 本文が記録した余裕は「03:00 開始・約 16 分 → 次の distill 03:30 まで 14 分」だが、
3 本目は 03:18:49 に終わっており余裕は 11 分。3 本とも `verdict=completed` で衝突は
起きていないが、**RFC が書いた 16 分という前提を 3 本目が既に超えている**。
