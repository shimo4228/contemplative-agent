## Context

これは `docs/adr/README.md` の「ADR の種別」でいう **worldview ADR** である:
機構ではなく立場を記録する。

これまでプロジェクトには、望ましい最終状態の明示的な定義がなかった。
「X を作るべきか」の判断は、照らし合わせる固定の基準点なしに都度議論されてきた。
今後の作業から品質ベンチマークが派生してくることは予想されるが、先行する定義が
ないままでは、最適化対象として唯一具体的に存在するそれらのベンチマークが、
なし崩しに事実上の目標になってしまう。

能力目標として表現した north star —「より高性能で、より自律的なエージェント」—
も検討したが、framing として棄却した。2 つの既存コミットメントと矛盾するためである:

1. Contemplative 公理の Emptiness 条項: 目標は軽く保持し、単一の目標を最終の
   ものとして固定化しない（ADR-0002）。
2. Observation-over-steering の方針: オーナーは目標とする人格や行動を学習
   ループに注入しない（ADR-0050 / ADR-0051 / ADR-0052）。

最も近い先行言明は ADR-0017 の「プロジェクトの目標は transformation であって
elimination ではない」だが、これはシステムと困難の関わり方についての哲学的
フレームであり、「完成」が何を指すかの定義ではない。

本 ADR は 2026-07-20 のオーナーとアシスタントの作業会話で決定された。

## Decision

望ましい最終状態を、能力目標ではなく**層別の完成条件**として定義する。
エージェントが何に*なる*かは意図的に未定義のままにする。定義できるのは、
実験装置がいつ完成したと言えるか、である。

1. **機構層（コード）** — 完成とはこの層が*動かなくなる*こと。変更は修理のみに
   なり、機構層の ADR はゼロに近づく。メタファー: 望遠鏡の改良をやめ、それで
   観測する。計器 / 監査ログ / chaos-TDD の系譜（ADR-0071 / ADR-0075 /
   ADR-0077）は、すでに「触らなくてよいほど信頼できる」への動きである。
2. **価値層（identity / constitution / skills / rules）** — 完成は到達点では
   *ない*。望ましい状態とは legible な進化が続いていること: 価値層のすべての
   変化が記録から追跡でき、オフラインで説明できる。この層に目標状態を定義する
   ことは observation-over-steering により禁じられている。
3. **研究層** — 完成とは、建立時の問い（contemplative constitution は小型
   ローカルモデルの行動を形づくるか。蒸留は複利的に働くか。identity は安定
   するか）に — 肯定・否定いずれであれ — 答えが出て、論文・エッセイに結晶し、
   machine-reference 圏に拡散されること。他者と LLM による派生が成功基準である
   （AI 時代のオーセンティシティ反転: scarcity より diffusion）。
4. **セキュリティ層** — 完成とは absence が維持されること。外部アダプタは
   1 つ（ADR-0015）、権限は増やさない（ADR-0007）。この層は*変わらないこと*で
   成功する。
5. **終わり方の設計** — 設計された終了は最終状態の一部である: read-only 計器が
   代謝の定常状態を示し、残る問いが別の実験（例: framework/worldview 分離の
   ための 2 体目のエージェント）を要求するようになったとき、6 時間ごとの
   heartbeat を止める。最終成果物は縦断記録 — データセット
   （`contemplative-agent-data`）と論文 — であって、エージェントインスタンス
   そのものではない。

一文で言えば: 望ましい最終状態とは、完成した観測装置の上で価値層だけが動き
続けている状態であり、durable artifact は走者ではなく走行の記録である。

**ベンチマーク非還元条項。** この定義から層別のゲートとして品質ベンチマークが
派生することは十分ありうるが、定義そのものは、いかなるベンチマークスイートにも
置き換えられない価値層の言明として固定する。ベンチマークは個々の層に仕える。
この定義の代替には決してならない（Goodhart ガード）。

## Review-when

期限なし（北極星の定義）。変更は日付付きの追補だけで行い、同じ PR で CLAUDE.md の北極星の節を同期する。

## Alternatives Considered

### 能力目標型の north star

「より賢く、より自律的なエージェント」を目標として掲げる。棄却: Emptiness 条項
および observation-over-steering と矛盾する。能力の成長はこのプロジェクトの
眼目ではない — 小型ローカルモデルで堅牢に動くこと自体が達成である。

### 定義しない（現状維持）

最終状態を未定義のまま、目的を都度議論し続ける。棄却: 改善判断のたびに目的を
ゼロから再審理することになり、派生してくるベンチマークが空白を埋めて、なし崩し
に目標になる。

### ベンチマークスイートを定義とする

品質メトリクスの集合に north star を代行させる。オーナーが明示的に棄却:
価値層のメトリクスへの還元であり、Goodhart リスクがある。

## Consequences

### Positive

- 今後の「X を作るべきか」の提案が固定の基準を得る: 機構層の提案は「収束する
  はずの装置の修理か、それとも改良か」で審査され、価値層への介入は「どこかへ
  誘導するか」ではなく「進化を legible に保つか」で審査される。
- `docs/CYCLES.md` に本 ADR を指す短い North-star セクションが追加される
  （正本は本 ADR。複製しない）。*（2026-08-26 追補 §C で部分的に反転: 操作面の
  要約は `CLAUDE.md` へ移り、CYCLES.md は短いポインタを保つ。）*

### Negative

- リスク: 「機構層が動かなくなる」は修理の凍結と誤読されうる — 修理・観測性・
  セキュリティ修正は完全にスコープ内に残る。終わるのは能力動機の機構拡大である。
- この定義は意図的に機械検証不能である。ドリフトは lint ゲートではなく週次の
  内省・診断サイクルで見張る。

### Neutral / Follow-ups

- 終了条件の具体化（heartbeat を正確にいつ止めるか）は将来の決定として予約し、
  タスク台帳（T-ENDSTATE-TERM）で追跡する。計器が代謝の定常状態を示したことを
  トリガーとする。*（台帳は 2026-08-25 に移送:
  現在は [rfcs/0006](../../rfcs/0006-heartbeat-end-state-criteria.md) —
  追補 §C 参照。）*

  > **注記（2026-09-28, rfcs/0006 withdrawn）**: 追跡エントリはオーナー判断で閉じた —
  > いつ止めるかは今考える問いではない。第 5 層の予約はそのまま残し、問いになったら
  > 新しく起票する。

## 追補 (2026-08-26) — 自律代謝と代謝の質

2026-08-26 のオーナーとアシスタントの作業会話で決定。きっかけは具体的な観測で
ある: 週次 insight パイプラインは 7 週間で 438 件の skill 候補を staging に置き、
採用は 53 件（12%）— 実効の濾過は headless reviewer で、人間ゲートはその推薦を
追認していた（ADR-0097 Context）。毎週人間側の腎臓 — 修理セッションと、大きな
週次 batch への追認ゲート — を要するループは完成した装置ではない。この観測が、
機構層の完成条件を書き下せる程度に具体化した。

形式: これは日付つきの**追加型**追補であり、supersede する新 ADR ではない。
元の決定 — 層別の完成条件、能力目標型の棄却 — は覆されずに立っている。日付つき
追補の形は ADR-0053 / ADR-0068 / ADR-0087 / ADR-0095 の先例に従う。
`docs/adr/README.md` の supersede 規則が対象とするのは決定の覆しであり、
worldview ADR の同一性は、元の本文を無傷のまま残し追加することで保たれる。

### A. 機構層完成条件の操作化

第 1 層の「動かなくなる」に、**共に必要な第 2 の判定**を与える: **環境との
フィードバックループ（Moltbook のエピソード → patterns → skills → 選択 →
生成 → Moltbook へ戻る）が、オーナーと Claude Code の日常的な関与なく自己調節
して回ること。** 人間の承認ゲートは権限として残る — attribution は人間に留まり、
承認系譜の系（ADR-0050）および sibling の
[agent-attribution-practice](https://github.com/shimo4228/agent-attribution-practice)
repo と整合する — が、その**負荷**はゼロに近づく。ループが毎週の人間修理を
要する間、あるいは人間が週次の候補 batch を濾している間、機構層は未完成である。

2 つの判定の合成規則: どちらも**必要条件**であり、単独では足りない。十分性は
意図的にオーナーの判断に残す（元の Negative が記録するとおり、この定義は機械
検証不能のままである）。自己調節に**到達するため**の有界な機構工事 — 満腹信号、
新規性の判定器 — は装置の修理としてスコープ内であり、能力の成長ではない:
「動かなくなる」は層が最終的に至る状態で、自己調節の判定は「止まることが早すぎ
ではなく正当である」のはいつかを言う。

境界を 3 つ、明示する:

- **棄却済みの能力目標型 framing の再開ではない。** ここで定義するのは完成した
  *装置*の性質（オペレータ負荷 → 0）であって、エージェントが伸ばす能力ではない。
- **人間ゲートの溶解ではない。** エージェントが人間の言葉なしに価値層の採用・
  退役を行う案は 2026-08-26 に検討し、棄却した: ゲートにおける人間の言葉は本
  プログラムの attribution practice の錨であり（ADR-0050）、それを外すのは、
  ループが自己調節で減らせる負荷のために attribution を手放す交換になる。
  第 1 層を抽象のまま残す案（追補しない）も検討し、棄却した: 438/53 の観測は、
  まさに抽象形では裁定できない事例だった。
- **steering ではない。** 下の B 条項の境界を参照。

### B. 代謝の質の条項

頻度単独では価値を判定できない。代謝の摂取側 — pattern を skill 候補へ抽出し
採用に供する**機構層の装置** — は、**複数の軸**で価値を見分けられなければ
ならない: 例えば新規性（store が既に知っているものからの距離）、重要度、環境の
反応。列挙は Emptiness 条項に従い意図的に開いたままにする。判定の単一スカラー
への還元は、ベンチマーク非還元条項と同じ理屈で禁止する。

この条項が付くのは**機構層** — 摂取装置の識別能力への要件 — であって、価値層の
内容ではない: 目標状態・人格・望ましいテーマは一切定義しないので、第 2 層の
observation-over-steering の禁止は無傷である。環境の反応は*読み値*として入る
のであって報酬の重みではない。採用を環境の報酬で重み付けする方式は、加えて
ADR-0051（trust weighting の退役）をその証拠ごと supersede しなければならない。

North star が名指すのは軸であって判定者ではない: 各軸を何が判定するかは下流の
設計問題として残す。重要度については ADR-0056 が現に立っている反対測定である —
同 ADR は LLM 採点を退役しただけでなく、事前登録した ablation（822 pattern で
Kendall tau 0.843、insight batch の top-3/top-5 順序が同一）によりこの摂取段での
評点の限界寄与が ~0 と示し、`importance` field の書き込み自体を止めた。その
証拠は立ったままである。ここで重要度を軸として名指すことは重要度計器の復活では
なく、将来の計器は ADR-0056 の ablation を明示的に supersede しなければならない
（ADR-0056 には本追補の日付つき対向注記を置いた）。

## 追補 (2026-10-24) — 最適化の先は無い。北極星は固着しないこと

2026-10-24 のオーナーとアシスタントの作業会話で決定。きっかけは「機構層が完成
したら、このプロジェクトは何なのか」という問いだった。オーナーの言葉:
最適化する先のないこのエージェントは何をしているのか分からない — コメントに
反応し、それがログになり、それを元に自己変化を加える。「常に変化し続けられる
こと、これのみが北極星なのかもな」。同じ会話でこの言葉は一段絞られた:
*変化している*ことと*変化し続けられる*ことは同じではない。

形式: 2026-08-26 と同じ日付つきの追加型追補。上の層別の完成条件は変わらず
立っている。本追補は、それらが*何のための*条件かを名指す。

### 最適化の先は無い

元の Decision は「エージェントが何になるか」を未定義のまま残した。本追補は、
その不在が埋めるべき穴ではないことを記録する。エージェントには目的関数も
報酬も目標状態も無く、足しもしない。欠けているのではなく、そういうあり方を
している — 最適化器というより生き物に近い。

### 北極星: 固着しないこと

このプログラムの北極星は、エージェントが変化し続けられることである。正確には
**固着しないこと** — 次に出会う縁に開かれたままでいて、自分だけを食べる閉じた
ループにならないこと。

変化それ自体は判定にならない。2026 年 5 月の self-post の記録が常設の例である。
ADR-0041 の後も生成器は毎セッション新しい文を出していたが、選ぶスレッドは自分の
語彙クラスタの周りを回っていた: 同じモデルである topic 要約器が自分の確立した
語彙に手を伸ばし、他者の言い回しを均してしまうので、エージェントは自分の出力を
再吸収し続けていた（ADR-0043。ADR-0060 が根と名指した自己参照的なレジスタ崩壊も
同じもの）。形の上では変化し続けていたが、実際には固まりかけていた。記録が
動いていることは、開いていることの証拠ではない。

### 機構層が完成した後に観るもの

機構層が止まること（第 1 層）が、この問いを読めるものにする: コードが動かなく
なれば、閉じていくループは装置が足元で変わったことの副作用ではありえない。
そこから先の観察の問いは**「変わったか」ではなく「閉じていないか」**である。
第 2 層の「legible な進化が続く」はそのまま残り、本追補はその進化の中で何を
見るかを読み手に告げる。

### 固着が認められたら機構層を変える

固着が認められたら、機構層は変える。これは修理と並んで、止まった層が再び動く
常設の理由であり、凍結の後も成り立つ: 「止まる」（第 1 層）は能力のためにコードを
育てないという意味であって、エージェントが閉じていくのに対して封をするという
意味ではない。閉じがどこから来ているように見えても、自分だけを食べるループは、
装置がエージェントを次の縁に開いたままにできていない — 何が届くか、どう消化
するか、何を読み返すか — ということで、それは計器の欠陥である。2026 年 5 月が
型になる: 直したのはエージェントに語彙を変えろと言うことではなく、他者の言葉を
自分の言葉に変えてしまう要約器を取り除くことだった（ADR-0043）。

変えるのは装置であって、価値層の中身ではない。エージェントをこじ開けるための
identity・憲法・skill・rule の文は書かず、目標のペルソナやテーマも名指さない。
価値層は自分のゲートを通してだけ進化し続ける。凍結後のこの種の変更は、観測した
閉じを名指す固着起因の再開（専用の dated note か ADR）として記録し、凍結の
読み値が能力動機の拡大と区別できるようにする。

### 境界

- **目標状態ではない。** 開かれていることは内容・ペルソナ・テーマではなく、
  向かうべき方向を名指さない。observation-over-steering（ADR-0050 /
  ADR-0051 / ADR-0052）は無傷。
- **変えるのは装置で、中身ではない。** 固着の観測は機構層を変える合図（上節）
  であって、価値層の中身を書いて開く方向へ誘導する合図ではない。
- **指標ではない。** 「閉じている」は読みであってスコアではない。既存の計器は
  材料になりうるが、開放度スコアは定義せず、単一スカラーで代表させず
  （ベンチマーク非還元条項、2026-08-26 代謝の質の条項）、判定はオーナーに残る。
  本追補は計器を建てない（ADR-0101）。
- **この一文も軽く持つ。** 空の条項に従い、教条に固まった北極星は自分の判定に
  落ちる。ここには日付つき追補の 1 本として置かれ、次の追補に開かれている。

- コード変更なし。完成ロードマップが予定する本 ADR への後続追補（2026-11 /
  2026-12）は本追補を通して読む: それらは装置がいつ完成するかを定め、本追補は
  何のために完成するかを述べる。それらが置く凍結の規則（例: 凍結後の commit は
  修理のみ）は、上の固着起因の再開を明示の例外として持つこと。

  読む。

## 追補 (2026-10-24) — 機構層の凍結とは何か

次の土曜ゲートで転記）。この追補は定義であって宣言ではない。凍結の **verdict** は窓が

### 計測単位と読みの規則

`scripts/freeze_reading.py` が毎週 1 行を weekly materials（`## Freeze Reading`）に出す。
4 系列: (i) 凍結集合を触った commit を ISO 週・種別（`fix` とそれ以外）で、(ii) 新設
mechanism ADR を月ごとに、(iii) `## Decision` / 機構節を変える追補を月・層別に（見出し単位の代理指標: 節の中身でなく追補見出しの追加を数える。消費計画・
Review-when・Decided-by・dated Note は `docs_motion` として報告のみで数えない）、(iv)
`tests/` の純増行数を週ごとに 2 系列（`tests/*_shell.py` とそれ以外）。読みの規則 3 行:
(1) 凍結集合を触った commit だけを読む、(2) `fix` 以外の type はすべて「動いた」、
(3) 凍結後の凍結集合への commit は `fix` 型 + RFC id（下の規則 1）。

読み方（定義でなく dated note）: 凍結集合が `fix` のみで、mechanism 層の新設 ADR も
mechanism 層の追補見出しも無い週が**静穏な週**（`## Layer` の無い ADR は mechanism として数える）。
静穏な週が ISO 週で 8 連続になると script は `freeze candidate` と出し、horizon 内の静穏週の
基礎率を併記する。基礎率が要る理由: 2026 年 W33〜W41 の静穏週は 9 週中 0 で、8 週連続は
現状の分布では到達不能であり、到達は分布が変わった読みである。計器行と `regime` commit
（下）は週を破らない。

### 凍結後の PR 規則

1. 凍結集合を触る PR は `fix:` 型で RFC id を持つ（RFC の `alignment:` は repair）。
2. 変更前に、再現する証拠（監査ログの行か失敗するテスト。ADR-0075 の replay）を commit trailer
   `Reproduces:` に置く。
3. 改名・移動・新 module・新 env キー・新 CLI フラグ・新 launchd label は含めない。表面 snapshot
   テストが赤になる変更は ADR 追補と同 PR のみ。
4. `docs:` / `refactor:` 型で凍結集合を触らない（コメント修正は fix PR に同梱）。
5. `tests/` の変更は、再現テスト・snapshot 更新・項目の完了条件が列挙した既存テストの書き換え
  （「書き換える既存テスト: `tests/<file>::<test>`」）に限る。計器の合成 fixture テスト
  （`*_shell.py`）は計器側の再現テストとして許容する。列挙外の変更は script が `unlisted_tests` に出す。

機械検査は表面 snapshot テストと `freeze_reading.py`（`fix` 以外の type、`Reproduces:` 欠落、
`unlisted_tests`）で足り、新しい hook は置かない。

例外: 固着が認められて機構層を変える場合（上の追補「最適化の先は無い。北極星は固着しないこと」）は
規則 1–5 に縛られない。観測した閉じを名指す固着起因の再開（専用の dated note か ADR）として記録し、
凍結の読み値が能力動機の拡大と区別できるようにする。

### モデル交代は装置境界（D-P1-01-2 = A）

凍結後、生成・埋め込みモデルは論文 cutoff まで固定する。交代は強いられた場合（tag の撤去・
Ollama の非互換・セキュリティ）だけ。`OLLAMA_MODEL`・`OLLAMA_EMBEDDING_MODEL`・`_DEFAULT_*_MODEL`
を触る commit は種別 `regime` として `fix` とも違反とも別に読み、窓は数え直さない。ADR-0069 の
交代 trigger に同趣旨の日付つき停止注記を置く。重み blob を digest つきで手元保管するか、データ
カードに「not archived」と書くかは P3-05 で選ぶ（ここでは選ばない）。

### 「負荷」と「代謝は止まっていない」の読み方（D-P2-01-1 = B、D-P2-01-3 = B）

どちらも 2026-10-24 にオーナーが推奨どおり決定（P2-01.3 / .5 / .13）。負荷の定義は
人間の判断のままで機械化しない（2026-08-26 追補）。ここで固定するのは**読み方**。

- **負荷は 3 系列、並べて読み、合成しない**: (i) ゲートごとの裁定数（`gate_record`）、
  (ii) 読み量（Inventory の 5 数と Exceptions / Ledger / findings の行数）、
  (iii) ゲート外作業（`rfcs/README.md` 以外に触れたファイル数、
  whitelist・registry の編集）。並べて読む列は `origin: gate` 起票数・修理 PR 数・
  ゲート所要分。「裁定は 0〜2 件」だけで読むと、毎週 repo が変わっているのに機構層が
  完成したように見えるので、単一系列（D-P2-01-1 の A）は採らなかった。
  **スクリプトが現在読むもの**（既知の欠け。P2-01 の未了項目）: (ii) 読み量は
  **まだ列になっていない**（最新の Exceptions 件数を 1 つ出すだけ。週ごとの列は
  `reports/analysis/weekly-*.md` から読む形で P2-06.1 が足す）。一致率は表でなく
  census の「Gate record」節にある。(iii) `outside` は、ゲート commit を他と区別
  できないため**`Roadmap:` trailer の無い土曜 commit すべて**のファイルで近似する。
  ゲート以外の土曜作業（と squash merge した束 PR）も数える過大計上で、候補を
  妨げる向きにしか働かない（宣言する向きには働かない）。2026-11-28 のゲートで絞る。
- **読み手は 1 本**: `scripts/self_regulation_reading.py` が 8 週表を週次 materials に出す。
  (i) + (ii の起票) + (iii) が N 週連続 0（オーナーが決めるまで N = 8）で
  `self-regulating candidate` と宣言する。`gate_record` の無い週はゲート不在であって
  静かな週ではない。十分性はオーナーが次の `gate_record` に `self_regulation_verdict=`
  で書く。
- **ロードマップ自身の執行分は分けて読む**（P2-01.13）: `roadmap_start` / `roadmap_end` の
  分、`category=roadmap` の裁定、`Roadmap:` trailer つき commit のファイル数は別列で、
  3 系列の外。ロードマップを実行することで自己調節の候補が遅れも生まれもしない。
- **消費計画（ADR-0101）**: (a) 土曜ゲートが週次 materials の表
  （`## Self-Regulation Reading`）を毎週読む。(b) 2026-11-28 のゲートで D-P2-01-1 / -3
  （どの列を残すか）を決め、以後「負荷をゼロへ」の提案は 8 行に照らして判断する。
  (c) オーナーの判定を記録し候補が N 週続いたら週次表を退役し、四半期の T4 が
  以後を読む。チェーンは金曜を `--end` に渡すので、土曜ゲートが未実行の最終週は
  「gate pending」とし、候補の連続とフロアから外す。
- **「代謝は止まっていない」の下限**（D-P2-01-3 = B）: `adopted = 0` かつ `archived = 0`
  かつ identity 更新 0 が 8 週連続になると、読み手が `metabolism floor reached` と出す。
  これは P4-01 の「終わり方の検討イベント」を起票する引き金（層 2 の読みに触れるので熟慮）で、
  定常状態の宣言でも停止でもない。下限が無いと、ログから「止まった」と「自己調節」が
  区別できない。
- **Re-read trigger**: 2026-08-26 追補は「負荷の読み値が出たら計器の要否を再読する」と
  予約していた。固定した最初の 8 週表（`docs/evidence/adr-0080/`）がその読み値で、再読は
  それを固定するゲートで行い、そのゲートの `gate_record` に記録する。

## 追補 (2026-10-24) — 終わり方の設計: 検討イベントであって条件ではない

オーナーが 2026-10-24 に決定（D-P4-01-1 = D、D-P4-01-2 = A、D-P4-01-3 = A で
N = 4 週、D-P2-01-3 = B で下限 8 週。いずれも推奨どおり）。形は 2026-08-26 の
追補と同じ日付つきの**加算的**追補で、元の Decision は覆さない。CLAUDE.md §
北極星の操作面の要約は同じ commit で同期する（2026-08-26 の規則）。見出しは日付形
のままとし、先の追補の小見出し A / B / C は再利用しない。

背景: 第 5 層は heartbeat の停止の「いつ」と「どうやって」を一緒に予約しており、
[rfcs/0006](../../rfcs/0006-heartbeat-end-state-criteria.md) は 2026-09-28 に
withdrawn になった（1 つの条件に賭け、その照合が 12 回素通りした。「定常を見てから
止め方を決める」は事前登録と逆順）。本追補は両者を切り離し、終了条件を決めずに予約
できるものだけを予約する。

**「いつ」と「どうやって」を分ける。**

- **終了条件は起票しない。** rfcs/0006 は withdrawn のまま。本追補は「定常」を定義
  せず、止めるべきだとも言わない。
- **どうやって**（オーナーが止めると決めた後の手順の順序）は wind-down runbook
  `docs/runbooks/wind-down.md` にあり、発動条件を持たない。
- **いつ**は*検討イベント*に置き換える: 観測可能なイベントが、オーナーが止めるかを
  検討するセッションを開く。イベントは**停止を含意しない**。誤発火の害はセッション
  1 回なので、1 条件でなく複数（いずれか）を予約する。

**検討イベント（いずれか 1 つで検討セッションを開く）。**

1. *研究の答えが出揃った。* 研究層の建立時の問いに公開の答えが出た（上の第 3 層。
   第 5 層の 2 条件のうち「残る問いが別の実験を要する」側）。研究層計画の答え表
   （`docs/plans/roadmap-2026-10/` の P2-01 / P3-01）で観測する。表が存在するまでは
   オーナーが土曜ゲートで読む。
2. *値層の代謝が止まった。* 値層の採用 0・archive 0・identity 更新 0 が 8 週連続
   （D-P2-01-3 の下限。第 5 層の「read-only 計器が定常を示す」側）。材料は週次の
   自己調節の読み（P2-01.5、予定）と値層の変化系列 `pipeline/value-layer/changes.json`
   （P2-05.7、予定）。
3. *Moltbook に 7 日到達できない。* 検知面は予定の `scripts/pipeline_watchdog.sh` の
   行「comment-report 不在 7 日」（P2-04.4 (c)）が `PIPELINE-STATUS.md` で ❌ になる
   こと。行が入るまでは、オーナーが土曜ゲート Step 0 で `PIPELINE-STATUS.md` の到達性
   を読んで代替する。
4. *プラットフォームの規約改定・閉鎖告知。* プラットフォーム仕様の人間の再読台帳
   （`docs/evidence/moltbook-platform-readings.md`、P1-07.19、予定）に規約改定・閉鎖
   告知の行が書かれる。無人チェーンはプラットフォームの仕様文を取りに行かない
   （`scripts/api_drift_scan.py`）ので、観測元は人間の台帳になる。
5. *ゲート不在。* 土曜ゲートの記録が 4 週連続で無い（N = 4、D-P4-01-3）。装置は
   ADR-0012 の設計どおり承認済みの値層で動き続け、自動の read-only 化も自動停止も
   入れない。止める判断は人間の行為のまま。`docs/GOVERNANCE.md`（P1-12、予定）の
   operator unavailability 節が N と agent-attribution-practice ADR-0008 との対応
   （値層 / 外部表面 / 停止権限）を記録する。

**判断役・材料・記録先。** 判断役はオーナー。材料は直近 N 週の週次計器 JSON（自己調節
の読み、パターン層の増分、値層の変化系列、staged 件数）で、本追補のために新しい計器
や script は建てない。「定常」はここでは定義しない: イベントが発火したとき、検討
セッションでその列から事前登録する（後付けで建てない）。注意書きを 1 つ: パターン層
（+300..+700 パターン/週）と値層（9 月に staged 0 が続く一方、identity と skills の
snapshot digest は変化）は、代謝が止まっているかについて現状で読みが一致しない。
検討の記録は、本追補の日付つき note、停止すると決めた場合の data repo `final` タグの
commit message、CHANGELOG の Ending 節。

**Moltbook の終端はこの走行の終端。** Moltbook の閉鎖または到達不能の恒久化は観察
走行の終端であり、別 platform への移植はしない（新しい実験は新 repo）。SNS 側の
Protocol も作らない（D-P4-01-2）。移植系の RFC が起票されたら、この段落を引いて
withdrawn にする。

上に挙げた各読み値は判定の材料であり、達したかの判定はオーナーが gate record に書く。

**再読トリガー。** 最初の検討セッションを開いたら、その日付と結果を日付つき note と
してここに残す。
