# ADR-0101: 計器の溶解義務 — 新しい計器は消費計画を明記する

## Status

accepted

## Date

2026-08-29

## Context

このプロジェクトには**建立**の義務があり、**溶解**の義務が無い。介入の前に測れ
（[ADR-0071](./0071-read-only-pattern-composition-instruments.ja.md)）は、介入の前に
読み値が要ると言う。observability by default
（[ADR-0075](./0075-observability-by-default.ja.md)）は、そのログを同じ PR で出せと言う。
撤去が書かれていないわけではない — ADR-0071 の Decision 2 は建立を両方向で signal-first に
しており、プロジェクト skill `read-only-instruments` は「signal-first both ways」と述べ、
ADR-0086 は自前の退役条項を持つ。欠陥は、それらの失効条件が**どのゲートも読まない prose に
散在している**ことである: 書かれていないのではなく、読まれていない。結果として、実務上は
畳む側が任意になる。2026-08-29 より前の 99 本の ADR のうち `## Review-when` 節を持つのは
4 本だけである（0069 / 0097 / 0098 / 0099 — `grep -l '^## Review-when' docs/adr/*.md` から
`.ja.md` の双子を除く。同日付の 0100 / 0101 は「より前」に当たらないので除外）。読み手が
一度も予定されないまま出荷された計器もある: co-selection family scan
（`scripts/coselection_families.py`）は出力がちょうど 1 回読まれ — その数値は ADR-0097 の
unit-C 注記に凍結された — スクリプト自体は本 ADR と同日に退役した（commit `a06c6be`、
2026-08-29）。`scripts/retrieval_recall_measure.py` も同様に予定された読み手を持たず、
ADR-0097 の Review-when 側の腕は将来の手動実行を待ったままである。

結果は実測できる。2026-08-29 時点で週次機構だけで約 17,769 行（scripts 6,286 /
src 3,178 / tests 8,305）ある。内訳（2026-08-29 実測）:

- **scripts（約 6,286、端数込み）** — `weekly-pipeline.sh` 861、`weekly-analysis.sh` 602、
  `value_layer_approval_join.py` 998、`value_layer_due_check.py` 552、
  `log_anomaly_sweep.py` 551、`docs_consistency_scan.py` 513、`api_drift_scan.py` 376、
  `cross_day_duplicate_scan.py` 356、`observation_ledger.py` 321、
  `state_invariant_check.py` 288、`pipeline_watchdog.sh` 216、`dead_code_scan.py` 163、
  `weekly_random_sample.py` 118、`pipeline_audit.py` 60、ヘルパー
  `_audit` / `_stats` / `_md` / `_scan` 179
- **src（約 3,178）** — `report.py` 329、`selection_metrics.py` 1,059、
  `never_selected_metrics.py` 808、`view_metrics.py` 388、`metrics.py` 189、
  `selection_window.py` 170、`episode_render.py` 235
- **tests（約 8,305）** — shell ガードのスイート 2,255、値層 2,026、スクリプトごとの
  fault column 2,671、report / metrics 1,353

窓 2026-05-01 → 2026-08-29 で tracked な Python は純増 +64,541 行（`3a759d4` 時点の実測。
endpoint 法 — 2 つの端点の総行数の差であって、commit ごとの diff の総和ではない）。計器
スライスはその成長のうち**同定できた最大の単一スライス**である:
[ADR-0097](./0097-consolidator-dissolution-and-skill-store-exit.ja.md) が導入した read-only
読み値は commit `186dee6` / `8757683` / `c9a1df4` で純増 +6,355 行の `.py` を足し、
`47616da` でその退役が消した −5,672 行を上回った — つまり **退役を正当化するために建てた
行数が、退役が消した行数を上回った**。窓全体に占める計器の総取り分は測っていないので、
これは実測された 1 事例であって「計器が総量を支配する」という主張ではない。個々の
スライスはそれぞれ正当化されていた。合計は誰の判断でもなかった。

欠陥は個々の計器ではなく非対称そのものである。建立が必須で溶解が任意なら、ローカルな
判断がどれだけ良くても在庫は単調増加する。これは北極星
（[ADR-0080](./0080-north-star-layered-end-state.ja.md)）と逆行する。その 2026-08-26 追補が
現行の判定形である: 環境とのフィードバックループがオーナーの日常的関与なく自己調節しない
間は機構層は未完成であり、追補は自己調節を前進させる限定的な機構作業を明示的に許している —
したがって「機構を増やした」こと自体は違反ではない。それでも非対称は追補後の基準に反する。
**消費されない**計器は、自己調節を一切前進させないまま運用者の負荷 — 追補自身の指標である
「人間の承認負荷がゼロへ近づくこと」— を上げるからである。

## Decision

1. **新しい計器はすべて消費計画を記載する。** ここでいう計器とは、作用させるためでなく
   読まれるために建てられた read-only の読み値・分布・較正スケール・監査面すべてを指す。
   その ADR（台帳から入るなら RFC）は次を述べなければならない:
   - **(a) 誰が・いつ読むか** — 名指しの消費者と、cadence または発火イベント。
     「必要になったとき」は不可。
   - **(b) 何回の読みで何を決めるか** — 読み値が入力される判断と、それを閉じる読みの回数。
     **例外**: ADR-0071 型の探索的な計器 — 読み値が存在するまで介入を選べないからこそ
     建てるもの — は、閉じる読みの回数の代わりに**日付つきの review 時点**を述べてよい。
     読み手と review 日付は依然として名指しが要る。免除されるのは回数だけである。
   - **(c) 満了時の撤去条件** — 何をもってこの計器が終わりになり、いつ降ろすか。

   **消費計画を書けない計器はゲートで不採択とする。** (a)〜(c) に答えられないことこそ、
   その計器に消費者が居ないという signal であり、本 ADR が捕まえたい失敗形である。

2. **計画は所有 ADR の `## Review-when` 節の中、`### Consumption plan` という小見出しの
   下に置く**（台帳生まれの計器なら RFC の frontmatter か本文）。計器 1 つにつき 1 箇所、
   それを生んだ判断の隣に置く — それ自体の保守を要する別の登録簿は作らない。小見出しに
   よって失効条件と消費計画が grep で区別できるままになるので、棚卸しは失効条件を全部
   読まずに計画だけを見つけられる。

3. **拒否する主体は、その ADR / RFC を受理する人間のゲートである。** 無人の週次チェーンが
   起票した計器 draft なら、土曜の `/weekly-gate` セッション。対話的な ADR なら commit 時の
   著者で、`adr-reviewer` のパスに「消費計画の欠落を指摘せよ」と指示する。拒否は
   **draft が理由 1 行つきで未受理のまま留まること**として記録する — 新しい成果物も
   却下台帳も作らない。

4. **Rollout — 縮小プログラムのトランシェ T4。** 既存の計器に対する遡及棚卸しを、週次機構
   から始める。対象集合は **実行のたびに再導出する** — 2026-08-29 に用いたのと同じ
   消費者 / 意図の掃引による: `git ls-files scripts/`、CLI コマンド表、
   パイプライン script の冒頭コメントと計器 ADR の `Review-when` が名指しする計器を集め
   （2026-09-05 までは `docs/CODEMAPS/architecture.md` の Data Flow 節を読んでいた。codemap は
   [ADR-0102](./0102-retire-codemaps.ja.md) で退役）、消費者は launchd
   plist / パイプラインスクリプト / runbook と、生きた意図は所有 ADR の `Review-when` と
   RFC の state と突き合わせる。**常設の登録簿は持たない** — この手順で再導出できるうえ、
   登録簿は保守対象がもう 1 つ増えるだけだからである。初回: 2026-08-29 に発注済み
   （本トランシェと同時に dispatch した repo 全体の意味的棚卸し）。以降は各四半期境界の
   後の最初の土曜ゲート。計器ごとに、消費計画が述べられる（そして記録される）か、退役候補に
   なるかのいずれかとする。判定は所有 ADR への日付つき注記として記録し、ADR-0044 の
   読み方に従う: 述べられた失効条件がすでに発火している計器に、残る根拠は無い。

5. **既存計器の扱い（grandfathering）。** 2026-08-29 より前に受理された計器 — ADR-0099 の
   観測台帳とその seed 固定ランダムサンプルを含む — は、遡及的な不採択ではなく T4 の
   backfill から入る。Decision 1 が拘束するのは新規の建立だけである。

6. **これは記述の義務であって機構ではない。** 新しいコード・スケジューラ・lint ゲート・
   登録簿ファイルを作らない。義務はすでに書かれている文書に 3 文を足すことで果たされ、
   その ADR を受理するのと同じ人間のゲートが強制する。

**トランシェの記号** — 2026-08-29 の縮小プログラムが使う名前。兄弟の記録を読む人のために:

- **T0** — 2026-08-29 の即時削除（本トランシェ）。
- **T1** — 未割当。義務の commit が番号なしで着地したため。
- **T2a / T2b** — 読み窓の裁定。2026-09-03（RFC-0011）と 2026-09-05（RFC-0014 + RFC-0015）。
- **T3** — RFC-0012、shadow constitution の消費。次回の改正ゲート（〜2026-11）で裁定。
- **T4** — 本 ADR の遡及棚卸し（Decision 4）。

## Review-when

- 連続 2 回の遡及棚卸し — Decision 4 の導出手順で走る T4 の実行で、土曜ゲートが判定する —
  で、退役候補ゼロかつ消費計画を欠く新計器ゼロ → 習慣が内面化したということなので、
  本義務を ADR-0071 の prose へ 1 文として畳み、本 ADR を退役する。
  （Scaffold Dissolution の inward: 実践が担うようになった時点で rule は足場でなくなる。）

## Alternatives Considered

### 削減モラトリアムの宣言

一定期間、新しい計器の建立を凍結し、その間を削除に充てる案。2026-08-29 に著者が却下:
期限つきの凍結は一度きりの削減を買って失効し、在庫を生んだ非対称はそのまま残る。著者は
凍結ではなく常設のルールを選んだ。

### 同一機構の第 3 改修で再設計するルール

「同じ機構が 3 回目の amendment に達したら、パッチでなく再設計する」。不採用。実在する
パターンではあるが、直そうとしている欠陥より狭い — 1 つの機構の反復修理を扱うのに対し、
実測された駆動源は多数にわたる消費されない建立である。独自の証拠が立った時点で改めて
提案すればよい。

### 計器の行数に数値上限を置く

「1 計器は N 行を超えない」「計器コードは src の X% を超えない」等。却下: 証拠を伴わない
数値ゲートは測定の規律が禁じているものそのものであり、欠陥は「読み手の居ない計器」で
あって行数では見えない。誰も読まない 200 行の計器が問題であり、週次の消費者を持つ
2,000 行の計器は問題ではない。

### 決定論的な ADR 検査を拡張して節の存在を検査する

`scripts/docs_consistency_scan.py`（または `tests/test_adr_status_consistency.py`）に、
`### Consumption plan` を持たない計器 ADR を落とさせる案。不採用: 存在は機械的に検査できるが
**十分性は検査できない**。存在だけを見るゲートは grep を満たすためだけの定型文を招き、
判断を緑のチェックへ変換してしまうぶん、ゲートが無いより悪い。人間のゲートが計画の欠落を
実際に見落としたら再訪する。

### 消費されていない計器を今すぐ消し、常設ルールは書かない

ADR-0095 の形 — 引き算で肥大を解き、ルールは省く。削除は実際に走った（同日のトランシェ T0）。
それだけでは足りない。一度きりの削除は**流入**に届かないからで、次に建つ消費されない計器は
その削除の影響を受けない。ルールは、削除が構造上届かないところを対象にしている。

### 現状維持

Context の実測により却下。建立側だけの義務と、99 本中 4 本の `Review-when` という状態は
収束する系ではない。

## Consequences

### Positive

- ゲートが、最も強い証拠 — 誰が読むかを誰も言えない — に基づいて、計器を誕生時点で
  拒否できるようになる。
- 約 17.8k 行の週次複合体に、無期限の猶予ではなく期日のある清算（T4）が付く。
- 失効条件が計器ごとに 1 箇所へ集まり grep 可能になるので、後の棚卸しは prose から意図を
  導出し直さず `### Consumption plan` の小節を読めば済む。

### Negative / accepted

- 消費計画は楽観的に書ける。名指しの読み手が実際に読んだかを検証する仕組みは無い —
  計画は主張であり、その主張が実際の経過に照らされる場が棚卸しである。
- 遡及棚卸しはゲートで行う判断作業であり、自動化できない。それは意図的である —
  自動化することは、本 ADR が作らないと決めた機構を作ることになる。
- **同日の ADR-0075 追補が、消費の主張を検証できたはずの成果物を取り除く。** その追補は
  read-only 計器をリプレイ可能ログの義務から外すので、T4 の時点で「その計器が読まれた」と
  証明するログが無いことが多い。受け入れる緊張である: 消費の主張は計器自身の telemetry では
  なく、ゲートの記録 — 土曜のセッションがその読み値から実際に何を決めたか — で判定する。
- **Decision 1(b) の探索的な例外が強制力を狭める。** 介入が本当に未知な計器は、読み手と
  日付だけで、閉じる回数なしに義務を満たせる。これは (b) が本来求めるより弱い約束である。
  ADR-0071 型の作業を止めないための対価であり、日付つきの review 時点が、それが
  期限のないものになるのを防いでいる。

### Neutral

- CLAUDE.md 開発原則が 1 項増える。
- `.claude/skills/weekly-gate/SKILL.md` に、Decision 3 をゲート自身のチェックリストへ
  配線する 1 行が増える。
