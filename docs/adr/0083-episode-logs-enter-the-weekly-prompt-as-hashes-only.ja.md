# ADR-0083: エピソードログは週次プロンプトへハッシュとしてのみ入る

## Status

accepted

## Date

2026-07-25

## Context

週次レポート（[ADR-0040](./0040-separate-code-level-findings.md)）は
`scripts/weekly-analysis.sh` が組み立て、運用者向けの成果物に加えて 2 つの決定論的 intake を
`claude -p` へ渡す。`log_anomaly_sweep.py`（イベント流 — `*.log` と `audit.jsonl`）と
`state_invariant_check.py`（蓄積状態 — `knowledge.json` / `agents.json`）である。どちらも
モジュール docstring に load-bearing な禁止を持つ: エピソードログ `logs/YYYY-MM-DD.jsonl` を
決して読んではならない。外部由来の untrusted content を含み、出力は LLM に渡るからである。
同じ禁止は Claude Code セッション向けに CLAUDE.md にも書かれており、正規の読み取り経路として
`reports/comment-reports/` が指定されている。

その禁止が、支えられない主張に出会った。レポートの C — Duplicate 節は公開レコード間の同一性に
ついて述べるが、成果物に存在しないクロスエントリ主張を 2 回公開している:

- **2026-06-15** — 「6 日連続で同じ投稿へ re-reply」は、共有スレッドに返信していた 6 人の別々の
  相手だった。教訓は `config/prompts/principles.md` に**却下済みの機構**（post 単位 reply dedup）
  として記録されたが、それを生んだ**報告側の失敗**は記録されなかった。
- **2026-07-25** — 「記録上初のクロスデー完全一致出力」が、実在する 07-23 の 4 エントリと
  実在しない 07-21 の出現を組み合わせていた。7 月の全エピソードログに対して照合した結果、
  複数日に公開された本文はゼロ。レポートは重複の理由として 2 つの仮説を挙げ、運用者向けデータ
  からは決定できないと書いた。実際の答えはレポートが挙げなかった第 3 の選択肢 —
  その組み合わせは分析時に構成されたものだった。

どちらも散文としてはレビューを通った。**個々の**引用はすべて実在したからである。捏造されたのは
組み合わせだけであり、それを捕らえられるのは比較だけだった。これが duplication 指標と他の全エントリの
構造的な違いである: 他は単一エントリで、出典の日次レポートに対して構造上検証可能だが、
duplication の主張はエントリと日付を跨ぐ。

同時に、道具の割り当てを間違えている。2 つの文字列が同一かどうかはバイト比較で決まり、読解では
決まらない — `when-code-when-llm` skill の言う**構造的性質**である。パイプラインは 0.6 秒で終わる
計算を、長いプロンプトを跨いだ想起で LLM にやらせていた。

`config/prompts/principles.md` の Principle 5（2026-07-25 追加）は、クロスエントリ主張が決定論的
入力に依拠することを要求する。だが何かがそれを計算しない限り依拠先は存在せず、計算できるものは
すべてエピソードログの中にある。

## Decision

3 つ目の決定論的 intake `scripts/cross_day_duplicate_scan.py` を追加する。エピソードログを読むが、
そのハッシュ層の射影だけを出力する。

1. **境界は入力ではなく出力に置く**。`logs/????-??-??.jsonl`（日付ファイルのみ — `*.bak` /
   `audit.jsonl` / `skill-usage-*.jsonl` / symlink は構造上除外）を読み、出力するのは 4 種類の
   トークンだけ: 12 hex に切り詰めた SHA-256 ダイジェスト、整数のカウント、**ファイル名由来**の
   日付（自己管理下）、固定語彙 `{post, reply, comment}` の action 名。本文・`post_id`・
   `target_agent`・`internal_note`・`thinking` は一切現れない。post id を落とすのは意図的である:
   C 節が知る必要があるのは同一性が何件あるかであって、どの投稿が担っているかではない。
   ダイジェストは外部文字列の経路を開かずに群を一意に指す。

2. **語彙は閉じた文字集合として明記し、テストでゲートする**。`RENDER_CHARSET_RE` が許すのは
   ASCII 英数字・テンプレート自身の約物・`×` のみ。`TestOutputBoundary` が、注入した bait の
   断片単位の不在、id / 相手名の不在、そして任意入力に対する hypothesis property として
   「レンダが文字集合を広げない」ことを検査する。レンダに leak を注入すると落ちることを実証済み。

3. **完全一致のみ、正規化しない、デコードは strict**。ダイジェストは生の本文バイト列に対して取る。
   near-identical な言い回しは意味的性質であり、C 節が既に求めている register 観察として LLM 側に
   残る。これによりスキャンの答えは `sha256sum` を持つ誰にでも検証可能なままになる。
   不正な UTF-8 の行は寛容にデコードせず skip してカウントする: `errors="replace"` は異なる不正
   バイト列を同一の `U+FFFD` 文字列へ写すため、別々の本文が衝突して**存在しない重複を作り出しうる**。
   根拠のない同一性主張を拒むためのスキャンが、破損から同一性を製造してはならない。

4. **窓と全履歴を 1 パスで**。窓の読みは C 節が記述する対象、全履歴の読みは「記録上初」型の主張が
   要求するもの。窓だけを描画すると 2026-07-25 の失敗そのものの形に答えられない。日数は
   「日付ファイルの数」ではなく「公開本文があった日数」— 実際に比較した対象の分母だからである。

5. **不在は 0 ではなく文で述べる — ただしカバレッジの分だけ絶対**。クロスデー重複が一度も存在
   しないとき、レンダはそれを要約に突き合わせられる 1 行として述べる（2026-07-25 の失敗はカウントの
   読み違いではなく、検査を決定不能と名指した上でその主張を見出しに置いたこと）。skip したレコードが
   ある場合、その文は「実際に読めた本文の範囲で」と限定される。証拠より広い主張を拒むための計器は、
   まず自分の出力にそれを適用しなければならない。

6. **あらゆる fault は「数える skip」であり、crash ではない**。末尾切れ行・shape 違反・読めない
   ファイル・不正 UTF-8・孤立 UTF-16 サロゲートはすべて理由コード付きで skip し、その数をレンダに
   出す。これは行儀の問題ではない: シェルはスキャンの stderr を捨てて「not available」のスタブに
   フォールバックし、エピソードログは決して削除されないので、1 レコードの未捕捉例外は**計器を恒久的に
   かつ無言で退役させる**。日付ファイルのパターンが `\d` でなく `[0-9]` を使うのも同じ理由 —
   `str` パターンの `\d` は Unicode を許すが、レンダは日付を self-controlled と称している以上、
   パターンがそれを構造的に真にするべきである。

7. **state を持たない**。sweep と違い、新規性ベースラインを持たない絶対測定なので、消費するものが
   なく、同じ PR で sweep に必要だった不可分化の機構も要らない。exit code は常に 0 — 重複は公開出力
   についての事実であって corruption ではないので、`state_invariant_check.py` と違い呼び出し側が
   gate する対象がない。

8. **観測であって介入ではない**。レンダは「hash-equality dedup を介入として使うのは却下済みの機構
   （principles.md appendix）」と明記する行を持つ。プロンプト内のハッシュ表が、意図的にそうではない
   ゲートの根拠として読み戻されないようにするためである。

## Alternatives Considered

**エピソードログには触れず、comment reports を grep する**。comment reports は正規の読み取り経路で
あり、先週の findings が提案した standing manual check（`grep -l`）で近似できる。機械化の形としては
却下: reports はレンダリングであり、独自の truncation と整形を受け、しかもレポート窓しか覆わない
—「記録上初」には原理的に答えられない。捏造を止めるための測定は、レンダリングではなく記録を読むべき。

**ダイジェストと一緒に post id を出す**。人間の追跡には有用で、post id はサーバ生成の hex であって
自由文ではない。却下: C 節が必要としない利便のために外部由来のフィールドを 1 本開けることになる。
境界は「ダイジェストとカウントと日付だけ」と言えるほうが、例外リストとして持つより遥かに保ちやすい。

**窓だけを走査する**。安価で、現状の C 節には十分。却下: 修理対象の失敗は全履歴に関する主張であり、
9052 件 / 全履歴でも 0.6 秒。

**正規化ハッシュ / near-duplicate 検出（空白畳み込み、埋め込み類似）**。却下: near-identity は
意味的性質であり、それに答えた瞬間に目視で検証可能でなくなる。principles appendix が却下している
cosine similarity gate の方向へも漂う。

**何もせず Principle 5 に任せる**。却下: Principle 5 はクロスエントリ主張に決定論的入力を要求するが、
本スキャンが無ければレポート中で最も失敗しやすい主張にその入力が存在しない。満たしようのない規則は
良くて確率的にしか守られない — [ADR-0082](./0082-retire-observed-epistemic-key.md) の
enforcement-by-absence と同じ論法である。

## Consequences

- CLAUDE.md と既存 2 intake の docstring にある禁止は、絶対ではなく**精密**になった: Claude Code
  セッションは依然としてエピソードログを読んではならず、intake はハッシュ層の射影のみを出力する
  場合に限り読んでよい。将来スキャンの出力を広げたくなったとき、本 ADR がその参照先になる —
  広げることは書式の判断ではなく境界の判断である。
- `TestOutputBoundary` がその境界の機械的な形である。緩めるなら、理由は本 ADR の amendment に書く。
- C 節の完全一致主張は引用可能な入力を持ち、週次プロンプトテンプレートがその引用を要求する。
  near-identical な言い回しは読解のまま残るので、節の定性的な半分は保たれる。
- スキャンは毎回全履歴を読む。現在の生成速度（~65 件/日）なら数年は 1 秒未満に収まる。安価でなく
  なったとき、境界を入れるのは窓の行ではなく全履歴の行である。
- intra-day の再掲カウントが同じ grouping から追加コストなしで同梱される。それが実際に存在する
  現象であり（findings F3.2）、クロスデー 0 だけを報告すると「反復なし」と読まれる。
