## ADR の種別

このプロジェクトの記録は 2 種類に分かれる:

**問題解決 ADR (emergent)**
具体的な課題に触発された反応的な設計判断を記録する。この一覧に載っている記録の大半はこの種別。

例: ADR-0005 (SessionContext リファクタリング)、ADR-0008 (2 段階蒸留パイプライン)、ADR-0009 (importance score)、ADR-0016 (insight narrow / stocktake broad)。

**世界観 ADR (axiomatic)**
プロジェクトが最初から作動している mental model や哲学的フレームを記録する。これらは反応的ではない — **問題解決 ADR がそもそも定式化できる前提** として機能する。

例: ADR-0002 (論文準拠 CCAI 適用)、ADR-0007 (セキュリティ境界モデル)、ADR-0017 (唯識八識モデル)。

Template の `## Layer` はこの 2 分類を 5 値（`mechanism` / `instrument` / `governance` / `research` / `worldview`）に細分する。先頭の 4 つが問題解決 ADR にあたる。`## Decided by` と `## Layer` は ADR-0114 以降で必須（`tests/test_adr_status_consistency.py`）。既存の 113 本は backfill しない。

**判定のヒント**: その記録が「同じ問題を抱えた別プロジェクトでも違う形で書かれうる」なら問題解決 ADR。「プロジェクトの問題がそもそも読み取れるようになるための枠組み」を記述するなら世界観 ADR。

## テンプレート

新しい記録を追加する際は以下のフォーマットに従う:

```markdown
# ADR-NNNN: タイトル

## Date
YYYY-MM-DD

## Decided by
proposed-by: <起草者 — 例: Claude Code セッション>
decided-by: <受理した人>
date: YYYY-MM-DD

## Layer
mechanism | instrument | governance | research | worldview   （ちょうど 1 つ。上の「ADR の種別」の 2 分類のうち `worldview` 以外はすべて問題解決 ADR）

## Context
何が問題だったか、その日の事実

## Decision
何をしたか、なぜそうしたか（過去形で）

## Review-when
任意: どの観測・イベントでこの記録が古びるか（1 行、または「期限なし（理由）」）。read-only 計器を導入する記録は、その消費計画をこの節の中の `### Consumption plan` 小見出しに置く（ADR-0101）。棚卸しが失効条件と消費計画を grep で区別できるようにするため。

## Alternatives Considered
却下した案とその理由

## Consequences
この判断の結果どうなったか

## References
- `ADR-NNNN`（`NNNN-slug.md`）— この記録との関係を一行で
- 外部ソース（論文・先行事例・エビデンス）
```

注意: 価値層のチャネルを足す・消す・変える記録は、同じ変更で [ADR-0129](0129-value-layer-intervention-channel-registry.ja.md) の表を更新する。

## 運用ルール

- 番号は連番（0001〜）、時系列順。識別子は `ADR-NNNN` のまま
- 記録するのは、戻しにくい判断・文脈なしでは読み手が驚く判断・実際のトレードオフを決めた判断。それ以外は commit 本文（と RFC、CHANGELOG の 1 行）が持つ
- 後の判断は自分の記録か commit 本文を持つ。先の記録は書かれたまま置く
- 一覧の表は手で編集しない: 記録を足したとき、題・Date・日付つきの Amendment / Note を変えたときは `python3 scripts/adr_index.py` を実行する
- 新しい記録を足したら `graph.jsonld` にもノード（`description` は手書き）を足し、LLM 向けナレッジグラフを追従させる
- 一覧とファイルの整合性は `uv run pytest tests/test_adr_status_consistency.py tests/test_graph_integrity.py` と `uv run python scripts/docs_consistency_scan.py` で確認する
