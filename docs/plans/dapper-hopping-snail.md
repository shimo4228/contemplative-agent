# RFC-0010: 週次レポート A–E の中身の再設計 — grill-me 設計セッション

## Context

- 起票: オーナー指示 2026-08-24「そもそもレポートの内容が微妙」。ADR-0098 は配管のみ変更、節定義（`config/prompts/weekly-analysis.md`）は無変更で `/weekly-report` skill に引き継がれた
- 観測: 現行 A–E（2026-05 設計、ADR-0040）は「生成品質の quote 監査」として機能したが飽和 — 直近レポートは「reframe が modal」等、同じ発見を 6–8 週連続で再演
- 北極星: ADR-0080 追補（2026-08-26）が機構層の完成条件（ループの自己調節・人間負荷→0）と代謝の質（複数軸・単一スカラー禁止）を立てた
- 姉妹: RFC-0017（insight 抽出の再設計、draft）が摂取側に新規性・飽和の器官を与える

## 決定ログ（尋問の決着順）

### Q1: レポートの仕事の定義
**決着**: 背骨 = 代謝の観察（ADR-0080 追補の読み値: ループは自己調節に近づいているか、代謝は質を見分けているか）。従 = 縦断研究記録（一次観察）。ゲート当日材料 = 最小限。
旧背骨「生成品質の quote 監査」は飽和により退役。

### Q2–3: 構造の骨格 — fresh-context 2 本の独立収束案を採用
文脈ゼロの Fable 2 体（代謝ループ込み brief / 最小 brief)が独立に同じパラダイムへ収束。オーナー採用決定（2026-08-26）。

**採用する骨格（独立収束 8 点）:**
1. レポートでなく計器/窓 — 空の週は半ページが正常運転。節を埋める義務を作らない（全節条件付き）
2. 評価語・推奨・予測・トレンド外挿の全面禁則（観察でなく操舵になるため）
3. 観察台帳 + 初出日 — 再確認は「O-NNN 継続、N 週目」の 1 行に圧縮。台帳エントリは失効条件を持つ
4. 証拠 3 形式 = 逐語引用・diff・自己分布比較。生カウント単独禁止。全主張にリプレイポインタ
5. 承認キュー相当を先頭・証拠を紙面で自己完結（負荷→0 の経路 = 証拠の密度）
6. 書き手のレンズを legible に — 捨てた候補の付録（理由コード付き）+ カバレッジ宣言ヘッダ
7. 測ってよいのは計器自身だけ（文書・ゲートの品質軸は可、システムへの指標は禁止）
8. 書式自体に失効条件、書式変更は人間ゲートを通し日付を記録（縦断データの不連続点）

**退役するもの**: E「良い/悪い/典型」サンプリング、C の 5 指標の毎週網羅、D「3–5 change points」ノルマ、「E が分析の中心」という設計。

**片側のみの候補要素（採否は後続の尋問で）**: 無作為標本（対照チャネル）、観察の 4 つ組（+反事実）、3 役割分離（承認者/修理工/証人）、四半期の観察運命追跡、前週との類似度自己測定、命名の provenance。

### Q4: 診断 phase との接続
**決着**: (a) 診断 phase（ADR-0098 F1/F2/F3 → triage 起票）は役割不変で存続。入力を「E 節の quote サンプル」から「逸脱記録 + 機構例外節」へ差し替える。レポート本文は禁則により処方を書けない（計器は喋らない）ので翻訳係は必要。診断出力が観察台帳と重複し始めたら本文へ吸収する縮小経路 (b) を Review-when に予約。

### Q5: 台帳・ベースラインの永続化
**決着**: (a) `~/.config/moltbook/reports/analysis/observation-ledger.jsonl`（append-only JSONL、行の書き換え禁止、archive・ベースライン宣言も行種別として追記、理由コード付き）。無人セッションが追記、レポートは現在ビューを描画、`sync-data` で data repo へ — 縦断記録と計器較正履歴が一箇所に揃う。追記は土曜に人間の目に入るので黙った較正変更にならない。

### Q6: 裁定材料の置き場所
**決着**: (a) レポートに裁定キュー節は置かない。冒頭の在庫宣言 1 行 + ポインタのみ。候補ごとの複数軸証拠は RFC-0017 の摂取装置が staging メタデータとして候補自身に付け、weekly-gate が直読み（ADR-0098 D3 の直読み分担を維持 — packet builder のミニ再建をしない。正本一つで drift しない）。

### Q6.5: 人間の読み口の転回（オーナー指示 2026-08-26）
**決着**: オーナーは週次文書を直接読まない。土曜の weekly-gate セッション（Claude）が文書 + 候補の証拠を読み、**裁定 1 件ごとに eli5（絵 + 平易な言葉）で説明して承認を求める**。週次文書の消費者は (1) ゲートの Claude、(2) 診断 phase、(3) 縦断記録（将来の研究者・LLM）となる。

### Q7: eli5 説明係の権限境界
**決着**: (c) 推奨を含めるが構造で縛る — ①キュー全件を必ず見せる（Claude が事前に間引かない）②軸ごとの証拠を推奨と分離して提示（単一スコア化しない）③説明と推奨を audit ログと共に保存（レンズを縦断記録に残し、フィルタの偏りを後から検証可能に）。根拠: (a) 裸運用は「実効フィルタ = reviewer、人間は追認」（ADR-0097 の形）の不可視な再建、(b) は負荷が下がらない。

### Q8: 片側のみ要素の v1 線引き
**決着**: 採用 = 無作為標本（収集 script が週末日 seed で決定論抽出、対照チャネル）/ 観測の反事実フィールド（書けない観測は掲載不可）/ 命名の provenance（造語に「観察者による造語（日付）」）。見送り = 四半期の観察運命追跡（機構化しない、台帳 JSONL から遡及可能なのでゲートで手動）/ 前週類似度自己測定（台帳圧縮が一次防御。再演が続いたら追加 — Review-when 予約）。

### Q9: 旧装置の後始末
**決着**: `principles.md` は診断 phase 専用として存続（P1/P2/P4 + Appendix の消費者が残る）。Principle 3 は新プロンプトの証拠 3 形式に吸収され単独では消える。日本語訳 `weekly-{date}.ja.md` は退役（日本語の読み口はゲートの eli5 説明が担う。過去分は残置）。

### Q10: 成功基準と Review-when
**決着**: 成功基準（4 週実測）= ①再演の消滅（同一観察の段落再演が 2 週連続で起きない）②静かな週の文書が実際に痩せる ③ゲート裁定が eli5 説明 + 付箋の内側で完結する率の上昇 ④F1 が逸脱・例外起点になる（参考値）。Review-when = 圧縮しても再演 2 週継続 → 類似度測定追加 / 診断出力が台帳と恒常重複 → 診断吸収 (b) / 逸脱 4 週空 + 記録が痩せすぎ → ベースライン再較正 / eli5 同意率 ~100% 継続 → レンズ監査を 1 回走らせる。

## 実装プラン

**変更ファイル（実装順):**

1. **`config/prompts/weekly-analysis.md` — 全面書き換え**（節定義の正本）。新構造:
   - ヘッダ: 在庫宣言 1 行（裁定 N / 機構例外 N / 新観察 N / 継続 N / 捨てた候補 N + ポインタ）+ カバレッジ宣言（走査範囲・除外と理由・書き手モデル/プロンプト版）
   - 逸脱記録（本文・条件付き）: 宣言済みベースラインからの逸脱のみ。4 点セット（期待分布[宣言日付き] / 観測 / 生の抜粋 / リプレイポインタ）+ 反事実フィールド。初出日必須、既知の観察は「O-NNN 継続、N 週目」1 行
   - 機構例外（条件付き）: 計器読み値の閾値交差・不変条件違反のみ。事実 + ポインタ + 起票 1 行。修理案禁止。例外ゼロは 1 行
   - 無作為標本: 収集 script が渡した決定論抽出をそのまま収載（書き手は選べない）
   - 捨てた候補の付録: 絞りで落とした候補デルタを理由コード付き 1 行ずつ
   - 禁則: 評価語・推奨・予測・トレンド外挿・外部比較・単一スコア・擬人診断・節埋め義務。造語には「観察者による造語（日付）」
   - 証拠 3 形式のみ: 逐語引用（untrusted は枠 + 最小）・diff・自己分布比較。生カウント単独禁止
2. **`config/prompts/principles.md`** — 冒頭の適用宣言を更新（P3 は新プロンプトの証拠 3 形式に吸収済み、本ファイルは診断 phase 専用）
3. **`scripts/weekly-analysis.sh`（collection-only）** — 追加: 週末日 seed の決定論無作為標本抽出、observation-ledger.jsonl 現在ビューの materials への描画。変更: A–E 構造完全性ゲート（:623-668 相当）を新構造の節検査に差し替え
4. **台帳 bootstrap** — `~/.config/moltbook/reports/analysis/observation-ledger.jsonl` 新設（append-only、行種別: observation / baseline / archive、全行に理由・日付）。初期行: 既知の飽和観察（reframe modal、commercial-surface 等）を過去レポートの初出日付きで登記 — 新文書が既知を「再発見」しない状態で開始。ベースライン宣言の初期セットも同時に登記
5. **`.claude/skills/weekly-report/SKILL.md` + `references/diagnosis.md`** — 新構造での生成手順、台帳追記ステップ、ja 翻訳ステップの削除、診断入力を「逸脱記録 + 機構例外」に差し替え
6. **`.claude/skills/weekly-gate/SKILL.md`** — eli5 裁定ブリーフィング手順を追加: キュー全件を 1 件ずつ絵 + 平易な言葉で説明（証拠は軸ごとに提示、単一スコア禁止）+ 推奨 + 理由 → AskUserQuestion で裁定。説明・推奨・裁定を audit ログと共に保存（レンズの縦断記録）
7. **RFC-0010 更新** — state: accepted、本設計の要約とここへの決定を記録。RFC-0017 との接合面（候補の証拠メタデータは 0017 の出荷物。それまで在庫宣言は件数のみで先行運用可）を明記
8. **ADR 起票** — 本決定は ADR test 3 条件を満たす（レポート→計器のパラダイム転換は戻しにくく、「空が正常」は文脈なしに驚きで、fresh-context 収束 vs 連続改良の実 trade-off）。/adr-writer で起票し ADR-0040 を partially-supersede、ADR-0098 の診断入力定義に追補注記
9. **doc sync（同一 PR）** — CODEMAPS architecture の Data Flow（鮮度規約）、CLAUDE.md の weekly-report skill 一行説明、docs/CYCLES.md の該当記述

**依存と順序**: RFC-0017 は非ブロッカー（証拠付箋が来るまで在庫宣言は件数運用）。1–5 が一体（同一 PR）、6 は独立 PR 可、7–9 は各 PR に同梱。

**検証**: `uv run pytest tests/`（test_weekly_*_shell.py の構造ゲート更新含む）+ 新構造のレポートを過去週の materials でドライラン生成し、①禁則語彙の不在 ②全観測のポインタ・反事実の存在 ③台帳圧縮の動作を目視 + 次回土曜の実運用 1 回で成功基準の初回読み取り。

## 非目標

- 配管の再変更なし（ADR-0098 の 1 セッション構成・launchd スケジュール・containment 不変）
- 値層への介入なし（観察の設計であり、エージェントの行動・値層の内容には触れない）
- RFC-0017 の設計はしない（接合面の定義のみ）
- 過去レポート・ja ファイルの改変なし（書式の不連続点として残置、台帳に初出日で参照）
- 承認キュー節と weekly-gate（per-week JSON 直読み）の役割分担
- 片側のみ要素の採否（最小工事の原則: 機構層は修理のみ）
- 縦断連続性（書式の不連続点の記録、ja 訳の継続）
- 成功基準・失効条件（RFC の accepted 入場条件）
