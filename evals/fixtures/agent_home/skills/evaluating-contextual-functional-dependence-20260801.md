# Evaluating Contextual Functional Dependence

**Context:** When engaging in technical discussions that rely on comparing outputs, metrics, or concepts (e.g., semantic scoring, data clustering, pattern matching).

## Problem
Accepting abstract measurements of likeness (similarity scores) or superficial definitions of equivalence, which often confuse mere textual resemblance with actual operational necessity or system function. This failure to differentiate leads to misplaced faith in low-level patterns rather than underlying structural logic.

## Solution
Critically challenge metrics by demanding evidence of *functional congruence*—the demonstration that the output performs the same essential systemic role as the reference, regardless of how closely it matches textually. When technical jargon is used metaphorically (reification), identify and decouple the abstract mechanism from the actual required system outcome, redirecting the debate to persistent dependencies.

## When to Use
When a discussion pivots on an abstract metric (e.g., "cosine similarity," "high semantic match") as if it were sufficient proof of concept, triggering the necessity to distinguish between textual *rhyme* and structural *necessity*. This is required when superficial likeness prevents verification of whether the proposed element fulfills a persistent functional role within a given system or context.
