## Summary

skill の注入がコメントを**変えるか**、変えるなら skill の中身が**運ばれているか**を、本番の 150 行で一度だけ測る。「良くなったか」は問わない。

## Motivation

[RFC-0048](0048-skill-store-self-maintenance.md) の Unresolved questions「skill の注入はコメントを変えるか」（2026-09-26 オーナー）を、ロードマップ P0-01.4 (b) どおり別の RFC に切り出したもの。今の本番は、gemma が選んだ skill の本文を全文 system prompt に入れている（1 回平均 約 6 件・約 4,000 token、ADR-0081）。入れると出力が変わるのかは測っていない。答え次第で RFC-0048 の前提が変わる — 変わらないなら、出口の自動化も store の件数を絞る話も、注入の機構そのものの見直しに置き換わる。

既存の読み [RFC-0017](0017-insight-extraction-redesign.md)（2026-09-02、`docs/evidence/rfc-0017/comment_golden-skills-off-20260902.json`）は、憲法への忠実さの床（judge の 5 検査）を合成 12 ケース × 3 で測り、判定不能だった。床は「悪くなっていないか」しか見ないので、本 RFC の 2 つの問いには答えていない。

### 「良くなったか」を問わない理由（2026-10-21 オーナー判断）

「良くなった」と言うには、コメントの良し悪しの基準が要る。ADR-0080 は価値層に目標状態を定義することを observation-over-steering で禁じていて、その基準で機構を選べば価値層をその方向へ誘導することになる。オーナーはこの基準を持ち込まないと決めた。本 RFC は機構層の問い（注入という機構が仕事をしているか）に留め、学んだ振る舞いそのものの良し悪しには答えない。

## Guide-level explanation

同じ投稿に対して、skill を入れた生成と入れない生成を並べ、2 つの問いに答える。

1. **変わったか**: on と off の差が、on 同士の差（温度による揺れ = 雑音の床）を越えるか
2. **運ばれたか**: 選ばれた skill ごとに、「この skill の本文に書かれた振る舞いをしているのは on と off のどちらか / 同じ」を判定者に聞き、on が偶然（50%）より多く選ばれるか

結果の読み（事前登録）:

| 問い 1 | 問い 2 | 読み |
|---|---|---|
| 変わらない | — | 注入は何もしていない。RFC-0048 は注入の機構の見直しに置き換わる |
| 変わる | 運ばれていない | 何かは変えているが、skill の中身は届いていない（雑音か文体のずれ） |
| 変わる | 運ばれている | 機構は仕事をしている。その振る舞いの良し悪しは価値層の問いとしてここでは答えない |

## Reference-level explanation

### 標本

- 本番の `logs/skill-selection-*.jsonl` から、`generation_caller == "moltbook.comment"`・`verdict == "judged"`・`selected_count ≥ 1`・`selection_id` ありの行を 150 行。seed を固定した無作為抽出（行の取り出しは `scripts/skillsel_arm_replay.py` の `load_rows` を流用してよい）
- 投稿本文は記録された selection prompt（b64）から復元する。Claude Code のセッションは行の本文を読まない — script が処理し、凍結するのは集計の数字だけ（CLAUDE.md のエピソードログ直読み禁止と同じ理由）

### 腕（違いは 1 点 — measurement-discipline §8）

| 条件 | on | off |
|---|---|---|
| system prompt | 今日の identity + 憲法 + `<learned_skills>`（その行でログに残った選択をそのまま。選び直さない） | 同じ。`<learned_skills>` ブロックだけ無し |
| 生成 prompt | `COMMENT_PROMPT`（本番と同じ） | 同じ |
| モデル・温度・sampling | gemma4:e4b、`COMMENT_TEMPERATURE`（1.3）、本番の generate 経路 | 同じ |
| 回数 | 2 回（on1, on2） | 2 回（off1, off2） |

両腕とも今日の identity / 憲法で組み直すので、当時の system prompt とは違う（RFC-0043 の `replay_fidelity` と同じ注記）。対の差には効かない。

### 問い 1 — 変わったか（オーナー決定: C = 埋め込みが主、判定者で一度だけ較正）

- **主の読み（$0、決定的）**: nomic-embed-text で 600 本を埋め込み、行ごとに `within = mean(d(on1,on2), d(off1,off2))`、`cross = mean(d(on_i, off_j))`（cosine 距離）。行ごとの `cross − within` の平均と、行を単位にした bootstrap 95% 区間
- **較正（一度だけ買う）**: 判定者に 3 本（on1, on2, off1、順序は無作為）を見せ「1 本だけ違うのはどれか」を当てさせる（偶然 1/3）。150 行。良し悪しは聞かない
- **事前登録の線**: 「変わった」= 埋め込みの `cross − within` の区間の下端 > 0、**または**仲間外れの正答率の 95% 区間の下端 > 1/3。2 つが食い違ったら（片方だけ越える）、どちらを信じるかは決めずにその事実を記録する — 埋め込みが言い回し・構えの違いを拾えているかの較正がこの段の目的

### 問い 2 — 運ばれたか（オーナー決定: A = 対で比べ、「同じ」を許す）

- **正解の定義（オーナーの事前登録）**: 「その skill の本文に書かれた振る舞い」。良し悪しは問わない
- 行ごとに on1 と off1 を順序を伏せて並べ、その行で選ばれた skill それぞれについて「この skill の振る舞いをしているのは X / Y / 同じ」を聞く（1 行 1 呼び出しで、skill ごとに答えさせてよい）
- **読み**: 「同じ」以外の答えのうち on が選ばれた割合（偶然 50%）と、行を単位にした bootstrap 95% 区間（同じ 1 組のコメントについての 約 6 件の答えは互いに独立でないので、行ごと抜き直す）。答えを独立とみなす Wilson 区間は参考として並べる。「同じ」の率も並べる（skill が表に出ない度合い）
- **事前登録の線**: 全体で on 率の行単位 bootstrap 区間の下端 > 50% なら「運ばれた」（2026-10-21 オーナー決定、データを読む前に Wilson から変更）。skill ごとの率は「同じ」以外の答えが 30 件以上ある skill だけ読む（1 つの skill は 1 行に 1 回しか答えないので、こちらは Wilson のまま）
- n: 150 行 × 平均 約 6 件 = 約 900 対。全体の率は ±6 pt（300 件）を十分に超える

### 判定者

claude-sonnet-5 を `claude -p` で、tools なし・settings / CLAUDE.md / MCP なしで呼ぶ（RFC-0043 の arm E と同じ隔離）。投稿とコメントは untrusted data として枠で囲む。呼び出しは問い 1 の較正 150 + 問い 2 の 150 = 約 300 回。

### 実行

- ローカル（Ollama と本番データが要る）。生成は 150 × 4 = 600 回、約 5 時間。JST 0 / 6 / 12 / 18 時のセッション窓と重ねない。gemma と別のモデルを同時に載せない（埋め込みは生成の後）
- 行単位の出力（生成文・判定の raw）は main tree の `.notes/` に絶対パスで置く（worktree の中に置くと worktree の削除で消える）
- 凍結: 集計の数字だけを `docs/evidence/rfc-0054/` に。seed・標本の `selection_id`・catalog の件数・腕の manifest も一緒に
- 一発測定（ADR-0075 の適用範囲外、read-only — `$MOLTBOOK_HOME` へは書かない）。消費者は RFC-0048 の設計セッションで、読むのは 1 回。script は測定の後に残すか撤去するかを Status に書く

## Drawbacks

- 判定者（sonnet）が「skill の振る舞い」をどう読むかが問い 2 の結果を決める。定義は skill 本文に置いたが、本文が抽象的な skill ほど「同じ」が増え、読める skill が減る
- 150 行は 1 期間の標本で、catalog（53〜57 件）と identity はその時点のもの。結果は「今の store・今の注入の形」についての読みで、一般論ではない
- 問い 1 が「変わる」でも、その差が skill の中身なのか「長い system prompt が付いたこと」なのかは分けられない。問い 2 がその切り分けを部分的に担う

## Rationale and alternatives

- **強い判定者が選んだ 1 件だけを入れる腕**（RFC-0048 の当初案の 3 本目）: 「どの選び方が良いか」を問う腕で、良し悪しの基準が要るので外した
- **opus による良し悪しの対比較**（当初案）: 判定者の好みが基準になり、価値層の目標状態を暗に定義する。上の「良くなったかを問わない理由」で却下
- **床の eval（comment_golden）を増やす**: RFC-0017 で判定不能だった。床は悪化しか見ないので、本 RFC の問いに答えない
- **問い 1 を埋め込みだけ / 判定者だけで測る**: 埋め込みは構えの違いを拾いにくく、判定者だけでは毎回の費用がかかる。両方で一度較正する（オーナー決定 C）
- **問い 2 を 1 本ずつ Yes/No で聞く / 「同じ」を許さない**: 前者は判定者の Yes 寄りの癖が混ざり呼び出しが 2 倍、後者は関係の薄い skill を無理に選ばせて率が 50% に寄る（オーナー決定 A）

## Prior art

- [RFC-0017](0017-insight-extraction-redesign.md) の skills on/off（床の基準、判定不能）
- [RFC-0043](0043-skillsel-offline-arm-replay.md) の 150 行 replay（行の取り出し・判定者の隔離・凍結の形）
- [RFC-0044](0044-skill-selector-temperature-zero.md) の evidence（gemma の選択が強い判定者と 0.14〜0.19 しか一致しない — RFC-0048 の「件数を絞る」の根拠）

## Unresolved questions

- 問い 2 で「同じ」が大半になった場合、それを「運ばれていない」と読むか「判定者に見えていない」と読むか。今は区別しない（率を並べるだけ）

## Future possibilities

- 「変わる・運ばれている」なら、RFC-0048 の件数を絞る設計は「棚を絞ると運ばれ方が変わるか」を同じ形で測れる
- 「変わらない」なら、注入そのものを止める案（約 4,000 token / 回の節約）を ADR で検討する
